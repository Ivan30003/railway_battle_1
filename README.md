# Паровоз

2D top-down survival / tower defence на рельсах. Проект на Python + pygame-ce.

Сейчас реализован **milestone 7** — круги, смена карт, победа и поражение:

- запускаемый скелет (окно, fixed-timestep цикл, сцены, ввод, конфиг);
- текстовый формат карт и строгий парсер с понятными ошибками;
- проверка, что все рельсы образуют один замкнутый цикл из `START` по `DIR`;
- построение маршрута с параметризацией по длине дуги;
- процедурная отрисовка рельсов, сетки и стартовой стрелки (в debug);
- паровоз с вагонами едет по замкнутому маршруту с заданной скоростью;
- счётчик пройденных кругов в HUD;
- монстры спавнятся у путей, преследуют паровоз и наносят ему урон;
- движущийся поезд давит монстров, получая золото и временное замедление;
- пушка паровоза управляется мышью и стреляет по ЛКМ;
- башни вагонов наводятся и стреляют автоматически, резервируя цели по
  режимам `target`, `primary` и `none`;
- миномёт наносит урон по области вокруг точки попадания;
- лёд наносит AoE-урон и складывающееся замедление монстров;
- взрывы, ледяные кольца и индикатор замедления видны на поле;
- убийства и давка приносят золото, стартовый запас задаёт `start_gold`;
- магазин покупает вагоны за золото, а цена следующего вагона растёт;
- купленный вагон сразу цепляется к поезду и получает свою башню;
- после `rounds_per_map` кругов карта считается пройденной и начинается следующая;
- при смене карты сохраняются золото, HP, вагоны и счётчик покупок;
- последняя карта завершает забег победой, а нулевое HP — поражением;
- экраны победы и поражения показывают статистику всего забега.

## Быстрый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

python -m game
```

Окружение `.venv` уже создано в репозитории и исключено из git.

Полезные варианты запуска:

```bash
python -m game --debug                 # сразу с debug-overlay
python -m game --scene game            # сразу игровая сцена
python -m game --scene shop            # игровая сцена с открытым магазином
python -m game --scene gameover        # превью экрана поражения
python -m game --scene victory         # превью экрана победы
python -m game --map maps/map2.txt     # одиночный забег по одной карте
python -m game --headless-frames 3     # smoke-запуск с dummy SDL
```

## Управление (milestone 7)

| Действие | Ввод |
|---|---|
| Подтвердить / играть | `Enter`, `Space`, ЛКМ по кнопке |
| Меню / закрыть магазин | `Esc` |
| Магазин | `B` или кнопка «Магазин» в HUD |
| Купить вагон | `1`–`4` или ЛКМ по кнопке в магазине |
| Огонь пушки | ЛКМ (можно удерживать) |
| Пауза | `Esc` в игровой сцене |
| Debug-overlay | `F1` |
| В главное меню | `M` |
| Выход | `Esc` в меню, `Ctrl+Q`, закрытие окна |

Поезд с локомотивом и вагонами (`start_wagons` в конфиге) сам движется по
замкнутому маршруту со скоростью `train_speed` из конфига. Вагоны держатся на
расстоянии `wagon_spacing` друг от друга. Каждый пройденный круг увеличивает
счётчик `КРУГ` в HUD; после `rounds_per_map` кругов карта считается пройденной.
На паузе и в магазине движение останавливается.
В магазине золото тратится на новые вагоны, поэтому покупки не происходят
посреди боя.

### Монстры и давка

- Монстры появляются только на краю экрана. Сторона выбирается
  противоположной ближайшему краю к среднему положению паровоза и вагонов:
  если поезд едет по правой части карты, враги выходят слева (в том числе
  в левых верхнем и нижнем углах).
- Начальный кулдаун спавна — `monsters_cooldown_start`. Каждая покупка вагона
  уменьшает его на `monsters_cooldown_step`, но не ниже `monsters_cooldown_min`.
  Кулдаун считается от накопленного `total_purchased`, поэтому уничтожение
  вагона не увеличивает его обратно.
- `monsters_probability_spawn_dist_start` задаёт вероятности типов монстров.
  Ключи должны совпадать с `monster_configs`, а сумма вероятностей — быть
  равна 1.
- Монстр преследует локомотив и атакует, когда оказывается в пределах
  `monster_attack_range` + его радиус, раз в `attack_interval`.
- Урон вычитается из HP паровоза (`locomotive_hp`). При нуле HP игра
  переходит на экран поражения.
- Движущийся поезд давит монстра, если тот попадает в
  `train_crush_radius` + радиус монстра. За каждого раздавленного начисляется
  его `gold`, а скорость поезда снижается до `crush_slow_factor` от обычной
  на `train_stop_per_crush_ms` миллисекунд (эффекты складываются; имя
  параметра историческое — поезд больше не останавливается). Пока поезд
  замедлен, монстры успевают атаковать.

### Пушка паровоза, башни и резервирование

- Пушка паровоза следует за курсором мыши. ЛКМ (можно удерживать) открывает
  огонь с интервалом `cannon.fire_interval`; дальность ограничена
  `cannon.range`. Выстрел — hitscan по лучу от паровоза к курсору: попадает
  первый монстр, чей радиус пересекает луч, поэтому целиться нужно вручную.
- У каждого вагона есть башня, которая работает автоматически. Радиус,
  скорость поворота, интервал, урон и порог наведения берутся из
  `wagon_configs`. Башня стреляет hitscan, когда её ствол направлен на цель.
- `priority` задаёт порядок типов монстров. При равном приоритете выбирается
  ближайший; если текущая цель всё ещё доступна и не хуже по приоритету,
  башня не переключается.
- `reserve` управляет резервированием целей:
  - `target` — цель эксклюзивна для этой башни;
  - `primary` — может отобрать цель у `target` и эксклюзивна среди `primary`;
  - `none` — игнорирует чужие резервирования и сам ничего не резервирует.
- Резервирование снимается при смене цели и автоматически чистится, когда
  монстр исчезает. Убитые монстры удаляются сразу, за них начисляется `gold`.
- `MORTAR` стреляет по области: урон получают все монстры в радиусе
  `aoe_radius` вокруг точки попадания (если радиус не задан у вагона —
  `mortar_aoe_radius`). Радиус взрыва проверяется с учётом радиуса монстра.
- `ICE` наносит AoE-урон и замедляет монстров в своём радиусе. Замедление
  складывается от каждого попадания, но не превышает `ice_slow_max`, а
  таймер обновляется на `ice_slow_duration`. Пока эффект активен, монстр
  движется со скоростью `speed * (1 - slow_percent)`. Сила замедления
  берётся из `slow_percent` вагона, иначе — из `ice_slow_per_wagon`.
- Взрывы миномёта и ледяные кольца рисуются на поле, а замедленные монстры
  получают ледяную обводку.

### Экономика и магазин

- Игрок начинает с `start_gold` золота. За каждого убитого или раздавленного
  монстра начисляется его `gold`; других источников дохода пока нет.
- Магазин открывается по `B` или кнопке в HUD и останавливает симуляцию.
  Закрывается он по `B`, `Esc` или кнопке «Закрыть».
- Цена следующего вагона общая для всех типов:
  `wagon_base_cost + wagon_cost_step * total_purchased`. После каждой покупки
  она увеличивается на `wagon_cost_step`.
- Купить вагон можно клавишами `1`–`4` или ЛКМ по кнопке. Если золота не
  хватает, кнопка неактивна, а покупка не происходит.
- Купленный вагон добавляется в хвост поезда, и для него сразу создаётся
  башня. Порядок вагонов в поезде и индексы башен остаются согласованными.

### Забег, смена карт и итоги

- Забег идёт по списку `maps` из конфига. На каждой карте нужно пройти
  `rounds_per_map` кругов; HUD показывает `КРУГ N/rounds_per_map` и
  `КАРТА M/всего`.
- Когда круг завершает карту, маршрут, монстры, башни и эффекты создаются
  заново для следующей карты. Золото, текущее HP паровоза, состав поезда,
  покупки и накопленная статистика сохраняются. Лечения при переходе нет.
- Последняя карта завершает забег победой. Если HP паровоза падает до нуля
  на любой карте, забег заканчивается поражением.
- Экран победы или поражения показывает, сколько карт и кругов пройдено,
  сколько монстров уничтожено, сколько золота заработано и сколько куплено
  вагонов, а также остаток золота.
- `Enter` или кнопка «Заново» начинает новый забег с первой карты.

## Карты и маршрут

Карты лежат в `maps/`. Формат:

```text
# комментарий
START=1,1
DIR=RIGHT
00 RD SH LD 00
00 SV 00 SV 00
00 RU SH LU 00
```

- `START=x,y` — координаты стартового тайла, `x` — столбец, `y` — строка,
  отсчёт с нуля;
- `DIR=UP|RIGHT|DOWN|LEFT` — направление, в котором поезд покидает стартовый
  тайл;
- остальные непустые строки — токены тайлов, разделённые пробелами.

Поддерживаются комментарии `#`, пустые строки, CRLF и UTF-8 BOM. Заголовки
могут идти в любом порядке до первой строки сетки.

| Токен | Значение |
|---|---|
| `00` | пустой тайл |
| `SV` | прямой вертикальный путь |
| `SH` | прямой горизонтальный путь |
| `X` | перекрёсток, поезд проходит прямо |
| `LD` | поворот вниз/влево |
| `RD` | поворот вниз/вправо |
| `LU` | поворот вверх/влево |
| `RU` | поворот вверх/вправо |

Парсер `game/core/map_loader.py` проверяет:

- размеры сетки и известность всех токенов;
- что `START` в пределах карты и указывает на рельс;
- что стартовый тайл соединяется в направлении `DIR`;
- что маршрут не выходит за карту и не упирается в пустой тайл;
- что маршрут возвращается в `START` с исходным направлением;
- что нет «осиротевших» рельсов, не входящих в цикл;
- что обычный тайл проходится ровно один раз, а `X` — не более двух раз
  (только навстречу друг другу под прямым углом, как в «восьмёрке»).

Ошибка загрузки карты печатается как `Map error: ...`, игра завершается с
кодом `2`.

Маршрут хранится в `game/core/path.py` как замкнутая ломаная. `sample(distance)`
возвращает позицию и единичный вектор направления, поэтому скорость поезда
не зависит от размера тайла и поворотов.

## Конфигурация

Все параметры — в `config/game.json`. Загрузчик `game/core/config.py`:

- подставляет значения по умолчанию для отсутствующих полей;
- глубоко сливает вложенные объекты;
- проверяет типы, диапазоны, типы вагонов, приоритеты и `reserve`;
- проверяет кулдаун спавна и распределение вероятностей монстров;
- выдаёт `ConfigError` с понятным сообщением.

Путь к конфигу можно переопределить: `python -m game --config path/to/game.json`.
Без `--map` забег идёт по всем картам из `maps`; с `--map` загружается только
указанная карта, и после её прохождения сразу наступает победа.

## Структура

```
game/
  app/       запуск, цикл, сцены
  core/      чистая логика без pygame (конфиг, карта, маршрут, поезд, монстры, бой, магазин)
  io/        события pygame → Action/InputState
  view/      renderer, камера, тема, UI, рельсы, поезд, монстры, башни, debug-overlay
  assets/    загрузчик изображений и процедурные заглушки
config/      game.json
maps/        map1.txt, map2.txt
tests/       pytest
```

Слой `core` не импортирует pygame, поэтому карты, маршрут, поезд, монстры и
боевая логика тестируются headless.

## Виртуальное разрешение и окно

Виртуальный холст вычисляется из загруженной карты:
`ширина × tile_size` на `высота × tile_size`. Для карт 20×15 при `tile_size=32`
это 640×480. При переходе на карту другого размера холст, letterbox и
раскладка HUD/магазина пересчитываются. Холст масштабируется в окно 1280×960 с
сохранением пропорций; окно можно менять в размерах.

## Ассеты

Сейчас используются процедурные заглушки из `game/assets/procedural.py`.
Чтобы подключить реальные изображения, положите PNG в `game/assets/images/`
и добавьте соответствие в `game/assets/manifest.json`:

```json
{
  "train/locomotive": "images/train/locomotive.png",
  "tile/SH": "images/tiles/SH.png"
}
```

Логические имена будут использоваться кодом; отсутствующие файлы автоматически
заменяются заглушками. Звуки пока не подключены.
